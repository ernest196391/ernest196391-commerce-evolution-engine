# Durable daily catalog queue

Offline SQLite foundation, no network or store writes. `CatalogQueue(path)` persists jobs keyed by tenant/product/input fingerprint, prioritizes higher scores, records attempts and events transactionally and limits claims to ten per UTC day per tenant by default. Retries count against that limit. Leases expire after 300 seconds by default; after three attempts interrupted jobs block. A random lease token prevents stale workers finishing reclaimed work. `finish` accepts only awaiting_review or blocked with result hash; no publish transition. `snapshot` lists product states without lease tokens. Use a persistent local disk, not ephemeral CI or a network share. Same fingerprint does not enqueue again; changed source snapshot needs a new fingerprint. Keep limit/lease settings consistent across workers. No credentials/PII in identifiers, events or result hash. Do not put DB in Git.

Verified: 23 local tests (6 new), including reopen/recovery, concurrent claim exclusivity, daily cap, tenant isolation, exhausted attempts, no publish. This is queue infrastructure, not a running daily agent or installed scheduler.
